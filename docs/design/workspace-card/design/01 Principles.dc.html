Principles

Seven rules that every surface follows. Each one has a don't (left) and a do (right). A design that breaks one of these is wrong, however good it looks.
1

Every count names its unit

✕ DON'T
● up 0/2PR open (1/1) · 1/1
✓ DO
0 of 2 upICM stage 2 of 4 · findings
2

Colour is never the only carrier

AA in light and dark
✕ DON'T
cli werkmeister-dashboard
✓ DO
● cli▲ werkmeister-dashboard unhealthy
3

One colour scale for everything

✕ DON'T
◌ WorkingCI runningOpen
Each row has its own colours, and purple is used for an open PR
✓ DO
okpartialfailingoffshipped
Containers, CI and the agent all use this scale. Purple is only for Merged and Released.
4

The highlight means one thing: Needs you

✕ DON'T
werkmeister-151-close-out-copy
green border = “containers up”?
✓ DO
werkmeister-143-wizard-defaults● Needs you
Every other card has a neutral border. The Containers row says the container state in words.
5

One legend per surface

DASHBOARD
Footer strip + help popover
MCP APP
Footer under the list
PANE
? toggle above the list
VS CODE
Help view, from the ? in the view title
Same content and order everywhere: highlight, colour scale, agent glyphs, service glyphs, PR states, ⚙. See board 09.
6

One verb per action, on every surface

✕ DON'T
StartLaunch✕ Remove
✓ DO
▶ Up✓ Close out✕ Abandon…
There is no Remove. The only destructive verbs are Close out and Abandon, and Abandon looks more destructive.
