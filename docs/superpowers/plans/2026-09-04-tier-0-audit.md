# Tier-0 Audit — the six verbs row 5 migrated

Plan 1 Task 5. The spec's §5 asserts these six already obey the §3 contract.
This checks that rather than trusting it.

The three questions, per verb:

1. Does it hold logic beyond argv mapping, rendering, exit-code mapping, TTY
   prompting and `process.cwd()` resolution?
2. Does its core call return data, or pre-formatted strings?
3. Does any `process.exit` sit outside the catch-own-code hint pattern?

**Verdict: all six are clean.** One change made — `connect` now passes an
`AbortSignal`.

---

## `up` (82 lines)

1. No. Argv, the cwd-dependent `resolveWorkspace`, `printSummary`, and the
   `feature === "infra"` re-dispatch into `connect` (deliberate, and documented
   in the file: that path prints connect's whole rendering, which `infra.up()`
   returns before).
2. Data — `UpResult` carries `slot`, `portRange`, `localServices`, `urls`,
   `servicePorts`; every string in the summary is built CLI-side.
3. `up.ts:59` only, for a missing feature name. Argv validation.

Now passes `interruptSignal()` (Task 4).

## `stop` (57 lines)

1. No.
2. Data — destructures `{ slot }` from `stopFeature`.
3. Two. `stop.ts:23` is argv validation. `stop.ts:44` is inside a `SandboxError`
   catch matching `NOT_RUNNING`, which exists because the "Start it with" hint
   has to print *between* the error line and the exit — the documented pattern,
   and the file says so.

## `restart` (50 lines)

1. No.
2. Data.
3. Two, same shape as `stop`. `restart.ts:44` handles two codes through a
   `hints` map (`NOT_RUNNING`, `COMPOSE_RESTART_FAILED`); everything else
   propagates to `main.ts`.

## `status` (342 lines)

1. No. Eight printers over `statusSnapshot()` / `interceptsSnapshot()`.
2. Data.
3. None.

The largest tier-0 file and the cleanest split — it is the model §3 rule 2 points at.

## `connect` (79 lines)

1. No. Banner, health table, developer-tools block.
2. Data — `infraHealth()` returns a name→boolean map; the CLI colours it.
3. None.

The three hardcoded `tools.local.sandbox.com` URLs stay CLI-side deliberately:
moving them opens where tool URLs are configured, which is a different question.

**Changed:** `infra.up()` now takes `{ signal }` and guards on it *before* any
setup work — the function writes proxy files, extracts a CA and configures a git
hooks path before it ever spawns compose, and a caller who has already cancelled
should get none of that. Measured: 8189ms of real work before the guard, 6ms
after. `startSharedInfra` also moved from `run` to `runAsync` so a mid-flight
Ctrl-C reaches the `docker compose up --build` that rebuilds k8s-forwards.

`sandbox.ts`'s `runConnect()` also calls `infraUp()`; it passes no signal and is
unchanged. Giving the dashboard and claudeck a cancellable connect is a consumer
change, out of this migration's scope.

## `hooks` (18 lines)

1. No. Dispatches `args.action === "gate"` to `gateMain()`.
2. N/A — the gate writes its own JSON verdict to stdout, which is protocol
   output and correctly stays a `console.log` (`gate.ts:292`). See the spec's §3
   rule 4.
3. None.

---

## Nothing for plans 2 or 3 to absorb

No tier-0 verb violates the contract, so neither later plan inherits work from
this audit.
